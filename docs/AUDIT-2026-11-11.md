# Aegis — Full Engineering Audit

**Date:** 2026-11-11
**Scope:** 12 module directories (11 with `package.json`, 1 empty), `server.js`, `scripts/`, `README.md`, `DELIVERY_REPORT.md`, 147 assertions across 23 test files.
**Method:** every claim was re-measured on this machine — tests re-run 20× for stability, HTTP behaviour probed with real requests, dependency gate executed, attribution scanned. Nothing below is taken from the delivery report without a measurement behind it.

---

## 1. Verdict

The architecture is real and the crypto surface holds up. The **delivery layer** did not: the test gate could not even start, the LAN signaling path was silently dead, and one malformed URL killed the server process. Eight defects were found and fixed; four written claims do not match the tree.

| Bucket | Count |
|---|---|
| Defects found and fixed | 8 |
| Claims verified true | 3 |
| Claims contradicted by the tree | 4 |
| Documentation / packaging gaps | 4 |

## 2. Defects fixed

### F1 — `npm test` had never run (blocking)

`scripts/run-all-tests.mjs` carried the path `modules/*/` inside a block comment. The `*/` closed the comment early, leaving the rest of the header as code:

```
SyntaxError: Unexpected identifier 'node'
```

`node --check` failed on the file itself. `npm test` — the only quality gate the repo documents — had never executed once. A gate that has never run is indistinguishable from no gate.

**Fix:** `modules/<name>/` in the comment. **Evidence:** `node --check` passes; `npm test` now completes in 1.3 s.

### F2 — `npm test` could never finish anyway

After F1 the aggregator discovered 23 files and hung on `modules/doc-redactor/tests/e2e.test.cjs` (Playwright, needs a real browser with GPU/WASM). Measured: 12 minutes running, never settling.

**Fix:** the aggregator skips browser-only suites and **prints what it skipped** rather than failing silently. The browser suite stays runnable explicitly:

```
node --test modules/doc-redactor/tests/e2e.test.cjs
```

**Evidence:** `npm test` → `discovered 23 test file(s)`, `skipped 1 browser-only file(s)`, `147/147 ALL GREEN (exit 0)`.

### F3 — one malformed URL killed the server (remote DoS)

`serveStatic` called `decodeURIComponent(url.pathname)` unguarded. A single request threw `URIError` outside any handler and took the process down:

```
GET /%ZZ      → curl 000   (connection got nothing)
kill -0 $PID  → process gone
```

Anyone who could reach the port could stop the service with one line.

**Fix:** `try/catch` → `400 bad request`. **Evidence:** `/%ZZ` → 400, the served page still 200, process alive.

### F4 — path prefix check accepted sibling directories

```js
if (!filePath.startsWith(ROOT))        // old
```

`ROOT` is `/Users/yangjie/Documents/Aegis`. A sibling `/Users/yangjie/Documents/AegisXYZ/` also satisfies `startsWith(ROOT)`, so its files would be served.

**Fix:** compare against `ROOT + path.sep`, and allow `filePath === ROOT` itself. **Evidence:** traversal → 404.

### F5 — LAN signaling was silently dead

`getRoom()` built the room object and returned it **without storing it in the map**:

```js
function getRoom(name) {
  let r = rooms.get(name);
  if (!r) r = { messages: [], cursors: new Map(), waiters: [], lastActive: Date.now() };
  return r;                            // never written back
}
```

So the GET long-poll and the POST sender each got their **own private room object**. The POST answered `{"ok":true}` — the message went nowhere. Measured before the fix:

```
POST /signal?room=T1&from=B   → 200 {"ok":true}
GET  /signal?room=T1&from=A   → 204 (20 s timeout, empty body)
```

This is the failure mode that survives every unit test, because both halves work in isolation: the sender always gets 200, the receiver always gets a clean 204.

**Fix:** `rooms.set(name, r)` inside `getRoom`. **Evidence after:**

```
GET  -> 200 {"msg":{"type":"offer","sdp":"v=0"}}
POST -> 200 {"ok":true}
```

Cross-room isolation re-checked: a message posted to `R3` does not reach a waiter in `R2`.

### F6 — signaling memory had no ceiling

Every POST pushed into `room.messages` forever; room count was unbounded. A dead peer or a room-name spray grows the process without limit — the 30-minute TTL only deletes rooms that already have zero waiters and at least one message.

**Fix:** `MAX_ROOM_MESSAGES = 200` (oldest dropped, ring behaviour) and `MAX_ROOMS = 2000` (new room refused with `503`). 200 in-flight signaling messages is far past any handshake.

### F7 — `token-gate` test flaky at 20 %

"a forged (tampered) token fails signature check" flipped **the last character** of the base64 signature. The trailing character of a 32-byte signature carries only padding bits — flipping it often leaves the decoded bytes identical, so the signature stays valid and the test asserts `false === true`.

**Measured:** 2 failures in 10 isolated runs.

**Fix:** flip the **first** character (high bits, always changes the bytes), with the reason in the comment. **Evidence:** 10/10 clean, then 20/20 full-suite runs clean.

### F8 — `detached-hash-signer` test flaky at 33 %

"tampering with the signature breaks verification" — same root cause, same trailing-character flip.

**Measured:** 5 failures in 15 full-suite runs.

**Fix:** identical. **Evidence:** 20/20 full-suite runs, zero failures.

> Note on F7/F8: this was a **test** defect, not a product defect. The verifiers correctly reject any signature whose bytes actually differ. The flaky tests were worse than useless — a red build at random trains everyone to ignore the gate.

## 4. Claims contradicted by the tree

### C1 — "Full-tree CJK / fullwidth-punctuation scan → CLEAN (English only)"

`DELIVERY_REPORT.md` §3.1 asserts the tree is English-only. **Measured: 30 files contain Chinese**, and not as scattered leakage — whole document sets are written in Chinese:

- `aegis-shell/README.md`, `aegis-shell/CHANGELOG.md`
- `token-gate` / `blind-relay` / `detached-hash-signer` / `sync-canvas` / `doc-redactor` / `encrypted-archive`: `README.md`, `CHANGELOG.md`, `TEST_REPORT.md`, `index.html`
- `sync-canvas/src/aegis-cosign.js` (39 comment lines)

Example: `aegis-shell/README.md:1` — `# Aegis Shell — Seven-Stage Closed-Loop Command Console`.

For an English-language B2B delivery this is not cosmetic: it means the module a buyer opens first is not in the language the report claims. **Decision needed:** translate to English, or restore an honest statement in the report.

### C2 — "Eight independent, reusable modules"

`README.md:110` says **Eight**. **Eleven** module directories carry a `package.json`. The table below it lists 8 and omits `token-gate`, `blind-relay` and `detached-hash-signer` — three of the more interesting security modules.

### C3 — "The relay only verifies the token signature"

`token-gate/README.md` describes a gated relay. `src/token-gate.js` is a pure library; the shipped `server.js` `/signal` endpoint **verifies nothing** — any client that knows a room name can post into it. The claim is true of an integration that wires `token-gate` in front of its own relay; it is not true of what ships in this repo.

### C4 — `p2p-crypto-transfer` assertion count

`DELIVERY_REPORT.md` states 10/10. **Measured: 11/11.** A stale count, not a failure.

## 6. Not verified — stated plainly

These need a real browser with a GPU and cannot be proven by unit tests. They are **unverified, not broken**:

- WebGPU topology render (10^6 nodes, SAB worker physics)
- In-iframe OCR in `doc-redactor`
- WebRTC handshake and AES-GCM chunk transfer in `p2p-crypto-transfer`
- The full seven-stage closed loop in the shell UI

The Playwright E2E in `doc-redactor` is the only automation for these and it cannot run headless here.
